## 2. Stage 1: パイロット（4〜8週）

| 週 | 作業 | 成果物 |
|---|---|---|
| 1 | プロバイダー選定・API 仕様入手・契約 | 技術評価書 |
| 1–2 | `ProviderAAdapter` の実装（本リポジトリのテンプレートを埋める） | アダプタ + テスト |
| 2–3 | Stratum V1 の実接続検証（testnet → mainnet） | 接続レポート |
| 3–4 | 実データでの Revenue Engine 補正（実 payout との差分を測定） | 補正係数の根拠資料 |
| 4–5 | PostgreSQL への切替・マイグレーション・RLS 有効化 | 本番相当 DB |
| 5–6 | staging 環境構築（Terraform 適用） | IaC 適用済み環境 |
| 6–8 | 社内少額運用・監視の調整 | 運用レポート |

**判断基準（Stage 2 に進む条件）**
- 実 payout と Revenue Engine の推定値の乖離が **±5% 以内**
- プロバイダー API の可用性が **99% 以上**（4週間の実測）
- ワーカー統計の欠測率が **1% 未満**

## 3. Stage 2: 限定公開（8〜12週）

| 領域 | 作業 |
|---|---|
| KYC | eKYC ベンダー選定・連携・審査フロー整備・制裁リスト照合 |
| 決済 | Stripe（またはアジア圏向け決済）連携・請求書・返金ポリシー |
| ウォレット | カストディ事業者の選定・審査・`WalletProviderInterface` 実装・少額での実送金テスト |
| 法務 | 利用規約・プライバシーポリシー・リスク開示書・特商法表記の作成と弁護士レビュー |
| セキュリティ | 外部ペネトレーションテスト・脆弱性診断 |
| 運用 | オンコール体制・エスカレーションフロー・ステータスページ |

**Stage 3 に進む条件**: ペネトレーションテストの High 以上がゼロ、実出金が 100 件以上無事故、法務レビュー完了。

## 4. Stage 3: 商用リリース（12〜20週）

- SLA 定義（99.9%）と補償条項
- 監視の本格化（APM・SIEM・異常検知アラート）
- サポート体制（一次受け・SLA 付き応答時間）
- 負荷試験（想定ピークの 3 倍）
- 障害訓練（DB フェイルオーバー・プロバイダー全停止・カストディ停止）
- ドキュメントの最終版化・トレーニング実施

## 5. Stage 4: ホワイトラベル展開（20週〜）

- テナントのセルフサインアップと独自ドメインの自動プロビジョニング（ACM / Let's Encrypt）
- テナント別課金（レベニューシェア or 固定 SaaS 費）
- テナント向け管理 API・Webhook
- 多言語（英語・中国語）
- AI Mining Optimizer の ML 化（`services/ai-predictor` を FastAPI で分離）

## 6. 技術的負債として意図的に残した項目

MVP では以下を「割り切って」実装している。商用化時に必ず対応すること。

| # | 項目 | 現状 | 商用化時の対応 |
|---|---|---|---|
| 1 | キュー | インプロセス実行 | BullMQ + Redis で別プロセス化 |
| 2 | セッション | DB（またはメモリ） | Redis へ移し、水平スケール時のレイテンシを削減 |
| 3 | Stratum | V1 の骨格（接続・購読） | 本番接続・再接続戦略・V2 |
| 4 | 実送金 | Mock（署名しない） | カストディ / HSM 連携 |
| 5 | メール | 未実装（アプリ内通知のみ） | SES / SendGrid |
| 6 | KYC | ステータス管理のみ | eKYC ベンダー連携 |
| 7 | 決済 | 未実装 | Stripe |
| 8 | 時系列 | 通常テーブル | パーティション化・TimescaleDB 検討 |
| 9 | AI | ルールベース | ML モデル（異常検知・需要予測） |
| 10 | i18n | 日本語のみ（構造は用意） | 英語・中国語 |

## 7. リスクと軽減策

| リスク | 影響 | 軽減策 |
|---|---|---|
| プロバイダーが契約を打ち切る | サービス継続不能 | 最初から複数社と契約。アダプタ方式で切替コストを最小化 |
| BTC 価格の急落 | 全ユーザーが赤字・解約 | 損益分岐点を常時表示し、事前にリスクを開示する |
| 難易度の急上昇 | 収益低下 | 難易度調整予測を表示。契約は短期プランも用意 |
| 半減期（次回 2028年頃） | 報酬が半分に | 契約期間・料金設計に織り込み、UI で明示 |
| 規制強化 | 事業停止 | 提供国を絞り、法務レビューを継続。撤退手順を事前定義 |
| カストディ事業者の破綻 | 資産凍結 | 複数カストディ・分散保管・自社 HSM の併用を検討 |
| 電力価格の高騰 | 収益悪化 | 電力コストを契約に転嫁できる料金設計、複数拠点 |

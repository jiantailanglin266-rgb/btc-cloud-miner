# 外部サービス依存関係

**原則**: すべての外部依存はアダプタ越しに使い、未設定時は Mock / フォールバックで動作する。
「この契約が無いと何も動かない」という状態を作らない。

---

## 2. 各依存の選定基準と候補

### 2.1 マイニングプロバイダー（最重要）

**評価項目**

| 項目 | 確認すべきこと |
|---|---|
| API | ワーカー単位の統計が取れるか / レート制限 / 認証方式 / SLA |
| 稼働率 | 過去12ヶ月の実績。SLA の補償内容 |
| 電力 | 単価・契約形態・値上げ条項 |
| 設備 | ASIC の機種・世代・効率（J/TH）・冷却方式 |
| 契約 | 最低契約期間・中途解約・ハッシュレート保証の有無 |
| 財務 | 事業継続性（前払いモデルは特に慎重に） |
| 法務 | 所在国の規制・KYC 要件 |

**リスク**: この業界は事業者の入れ替わりが激しい。**必ず複数社と契約し、1社への依存度を 50% 未満**に保つ。
本システムの `ProviderRegistry` は優先度付きフェイルオーバーに対応しているため、切替コストは低い。

### 2.2 マイニングプール

| 候補の型 | 特徴 |
|---|---|
| PPS+ | 支払いが安定（プールがリスクを負う）。手数料は高め |
| FPPS | 取引手数料も分配される |
| PPLNS | 変動が大きいが長期では有利 |

本システムは支払方式を `plans.payout_scheme` として保持し、Revenue Engine の期待値計算に反映できる構造にしてある。

### 2.3 Bitcoin ネットワーク情報

| 優先度 | ソース | 備考 |
|---|---|---|
| 1（primary） | 自社フルノード（Bitcoin Core RPC） | 最も信頼できる。商用では推奨 |
| 2（secondary） | 公開エクスプローラー API A | 無料枠あり。レート制限に注意 |
| 3（tertiary） | 公開エクスプローラー API B | 冗長化用 |
| 4（fallback） | 長期キャッシュ（stale） | 全滅時 |

**環境変数で URL を設定**し、未設定なら Mock ソースが使われる。
複数ソースの値が大きく食い違う場合は中央値を採用し、外れ値を警告する（`modules/bitcoin/service.ts`）。

### 2.4 カストディ / 鍵管理

| 方式 | 長所 | 短所 | 想定規模 |
|---|---|---|---|
| 外部カストディ（BitGo / Fireblocks 等） | 保険・運用込み。導入が速い | 手数料・カウンターパーティリスク | 小〜中 |
| 自社 HSM（CloudHSM 等） | 完全な管理権 | 運用負荷・鍵バックアップの難しさ | 中〜大 |
| MPC | 単一障害点なし | 実装・運用の複雑さ | 中〜大 |
| ハイブリッド | ホット＝カストディ、コールド＝HSM | 設計が複雑 | 大 |

**推奨**: 開始時は外部カストディ。取扱高が増えたらホット/コールド分離へ。
いずれの場合も `WalletProviderInterface` の実装を差し替えるだけで済む。

## 3. 依存の健全性監視

`GET /api/admin/health` が全依存の状態を返す。

```json
{
  "dependencies": [
    { "name": "provider:mock-farm-01", "status": "ONLINE",  "latencyMs": 12,  "lastOkAt": "..." },
    { "name": "provider:pool-rest-01", "status": "DEGRADED","latencyMs": 4210,"consecutiveFailures": 2 },
    { "name": "bitcoin:network",       "status": "ONLINE",  "source": "mempool", "freshness": "fresh" },
    { "name": "bitcoin:price",         "status": "DEGRADED","source": "cache",   "freshness": "stale:412" },
    { "name": "wallet:custody",        "status": "MOCK" },
    { "name": "db",                    "status": "ONLINE",  "latencyMs": 3 },
    { "name": "cache",                 "status": "MEMORY" }
  ]
}
```

| 状態 | 意味 | 表示 |
|---|---|---|
| `ONLINE` | 正常 | 緑 |
| `DEGRADED` | 遅延・一部失敗・stale データ | 黄＋最終更新時刻 |
| `OFFLINE` | circuit breaker 作動中 | 赤＋復旧予定 |
| `MAINTENANCE` | 計画停止 | 灰＋告知 |
| `MOCK` | デモ実装 | 紫（本番では出てはいけない） |

`MOCK` が本番環境で1つでも出ていたら、CI/起動時チェックで警告を出す（`NODE_ENV=production` かつ Mock 使用時）。

## 4. 契約時に確認すべき条項チェックリスト

- [ ] SLA（稼働率・補償・測定方法）
- [ ] API のレート制限と、超過時の挙動
- [ ] データの粒度（ワーカー単位か、契約単位か）と更新頻度
- [ ] 支払い方式（PPS+ / FPPS / PPLNS）と手数料の内訳
- [ ] 電力単価の改定条項
- [ ] ハッシュレートの下振れ時の扱い
- [ ] 中途解約・返金
- [ ] データの所有権・退出時のエクスポート
- [ ] 準拠法・紛争解決地
- [ ] 事業者の破綻時の資産の扱い
- [ ] 監査報告書（SOC 2 等）の有無

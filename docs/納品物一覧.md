# 納品物一覧

**納品の考え方**: クライアントがこのリポジトリを受け取れば、**別の開発会社でも運用・改修できる状態**にする。
そのために「動くコード」「なぜそう作ったかの設計書」「動かし方の手順書」「壊れた時の対処法」の4点を揃える。

## 7. 引き継ぎ時に別途必要なもの（本リポジトリには含まれない）

これらは**機密情報**のため、リポジトリとは別経路（パスワードマネージャ等）で受け渡します。

| # | 項目 | 備考 |
|---|---|---|
| A | 本番環境の認証情報 | Secrets Manager のアクセス権として引き渡す（値の直接受け渡しは避ける） |
| B | プロバイダー・プールの API キー | 契約書とセットで |
| C | カストディ / HSM のアクセス権 | 引き継ぎ時に必ずローテーション |
| D | ドメイン・DNS の管理権限 | |
| E | クラウドアカウントの管理権限 | |
| F | 各種契約書（プロバイダー・KYC・決済・カストディ） | |
| G | 法務レビュー結果・ライセンス関連書類 | |
| H | 本番データベースのバックアップ | 個人情報を含むため、取り扱いに注意 |

## 8. 受け入れ確認手順（クライアント側で実施）

```bash
# 1. クローン
git clone <repository-url>
cd btc-cloud-miner

# 2. 依存インストール
npm install

# 3. 環境変数ゼロで起動（デモモード）
npm run dev
```

- [ ] `http://localhost:3000` が表示される
- [ ] `demo@example.com / demo1234` でログインできる
- [ ] 2段階認証を設定できる
- [ ] ダッシュボードに数値とグラフが表示され、時間経過で変化する
- [ ] 期間切替（1h / 24h / 7d / 30d / 90d / 1y）が動く
- [ ] シミュレーターのスライダーを動かすと結果がリアルタイムに変わる
- [ ] 出金申請ができ、`admin@example.com / admin1234` で承認できる
- [ ] 管理コンソールでプロバイダーの状態が見える
- [ ] すべての推定値に「推定」表示がある
- [ ] `npm test` が全て通る
- [ ] `npm run build` がエラーゼロで完了する
- [ ] `docker compose up` で起動する
- [ ] 上記 §1〜§6 のファイルがすべて存在する

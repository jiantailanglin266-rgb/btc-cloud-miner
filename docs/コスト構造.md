# コスト構造

金額はすべて **試算例** であり、実際の見積もりではありません。
実数値は契約条件・為替・電力単価・BTC 価格により大きく変動します。

---

## 1. 事業としてのコスト構造（ユニットエコノミクス）

クラウドマイニング事業の収益は、次の式で決まります。

```
ユーザーへの提供価格
  −（ハッシュレート調達原価 ＋ 電力コスト ＋ プール手数料）
  −（インフラ費 ＋ 決済手数料 ＋ カストディ費 ＋ 人件費）
= 事業利益
```

### 1.1 変動費（採掘量に比例）

| 項目 | 内容 | 試算例 |
|---|---|---|
| ハッシュレート調達 | プロバイダーへの支払い | $15〜30 / TH/s / 年 |
| 電力 | ASIC の消費電力 × 単価 | 効率 17.5 J/TH × $0.06/kWh ≒ $9.2 / TH/s / 年 |
| プール手数料 | 採掘報酬の 0.5〜3% | 収益の 2% |
| 送金手数料 | BTC オンチェーン手数料 | 変動（mempool 次第） |
| カストディ | 残高比 or 取引比 | 残高の 0.1〜0.5% / 年 |
| 決済手数料 | クレジット決済 | 売上の 3.6% + 固定 |

### 1.2 固定費（規模にあまり比例しない）

| 項目 | 試算例（月額） |
|---|---|
| クラウドインフラ（下記 §2） | $250 〜 $2,500 |
| 監視・ログ SaaS | $50 〜 $500 |
| KYC ベンダー | 基本料 + 1件あたり $1〜3 |
| メール配信 | $10 〜 $100 |
| ドメイン・証明書 | $5 〜 $50 |
| 開発・保守人件費 | （最大の費目。体制次第） |
| 法務・監査 | 年 数百万円規模（暗号資産事業では必須） |

### 2.4 コスト最適化の勘所

| 施策 | 効果 |
|---|---|
| 時系列データのパーティション＋自動 DROP | DB ストレージが青天井にならない（最大の削減効果） |
| Redis キャッシュで外部 API 呼び出しを削減 | 外部 API の従量課金と自 CPU の両方を削減 |
| Fargate Spot をワーカーに使う | ワーカー費用を最大 70% 削減 |
| CloudFront で静的資産を配信 | オリジン負荷とデータ転送費を削減 |
| ログのサンプリング・保持期間短縮 | 監視費は放置すると DB 費を超える |
| Savings Plans / Reserved | 30〜40% 削減（構成が固まってから） |

## 3. ユーザーから見たコスト構造（透明性のため UI に明示する）

ユーザーのダッシュボードでは、収益の内訳を必ず全て開示します。

```
Gross Mining Revenue（推定）             $23.27 / day
  − Electricity Cost                    -$12.41   （206.9 kWh × $0.06）
  − Pool Fee (2.0%)                      -$0.47
  − Infrastructure / Platform Fee (2.0%) -$0.47
──────────────────────────────────────────────────
= Net Mining Revenue（推定）              $9.93 / day
  Profit Margin                          42.7%
```

**表示ルール**
- 手数料は率と実額の両方を出す
- 「推定」であることを必ず併記する
- 損益分岐点（BTC 価格・電力単価）を常に見えるようにする
- 契約前に「初期費用の回収に何日かかるか（ROI）」を提示する
- 収益を保証する表現・確定利回りの表現は使わない

## 4. 料金設計の考え方（テナントが設定可能）

| モデル | 内容 | 向き |
|---|---|---|
| 前払い型 | 契約時に一括。期間中のハッシュレートを提供 | B2C。事業者のキャッシュフローは良いが信頼が要る |
| サブスク型 | 月額。いつでも解約可 | 継続率が読みやすい。解約リスクあり |
| レベニューシェア型 | 採掘収益の N% を手数料として徴収 | ユーザーと利害が一致する。最も説明しやすい |
| ハイブリッド | 少額の基本料 + レベニューシェア | 実務的にバランスが良い |

本システムは `plans` テーブルで上記いずれも表現でき、テナントごとに料率を変えられます。

**重要**: 電力価格・難易度が上昇すると、ユーザーの手取りが減ります。
「電力コストを事業者が負担するのか、ユーザーに転嫁するのか」を契約で明確にしてください。
本システムは両方の表現に対応しています（`plans.electricity_price_kwh` を 0 にすれば事業者負担）。

## 5. 収支シミュレーション例（500 TH/s・1年契約）

前提: BTC $95,000 / ネットワーク 903 EH/s / 難易度 126.4T / 報酬 3.125 BTC /
効率 17.5 J/TH / 電力 $0.06 per kWh / プール 2% / プラットフォーム 2% / 稼働率 98.5%

（`src/modules/revenue/engine.ts` で実際に計算した値。`tests/revenue-engine.test.ts` で固定してある）

| 項目 | 1日 | 年間 |
|---|---|---|
| 推定採掘量 | 0.00024494 BTC | 約 0.0894 BTC |
| Gross Revenue | $23.27 | 約 $8,493 |
| 電力コスト（206.9 kWh/日） | -$12.41 | 約 -$4,530 |
| プール手数料 (2%) | -$0.47 | 約 -$170 |
| プラットフォーム手数料 (2%) | -$0.47 | 約 -$170 |
| **Net Revenue（推定）** | **$9.93** | **約 $3,624** |
| 利益率 | 42.7% | |
| 損益分岐 BTC 価格 | $52,780 | |
| 損益分岐 電力単価 | $0.1080 / kWh | |

### この試算から読み取るべきこと（重要）

500 TH/s の年間ネット収益が **約 $3,624** ということは、
**この契約を年 $3,624 より高く売ったら、ユーザーは必ず損をします。**

| 前払い価格 | ROI | ユーザーにとって |
|---|---|---|
| $12,000 | 1,209 日（3.3年） | ✕ 契約期間内に回収不能 |
| $6,000 | 604 日 | ✕ 1年契約では回収不能 |
| $3,000 | 302 日 | △ 条件が悪化しなければ回収可能 |
| レベニューシェア型 | – | ○ 損益が事業者とユーザーで連動する |

**したがって本システムは、前払い型よりレベニューシェア型を推奨します。**
前払い型を採用する場合は、ROI が契約期間内に収まる価格設定でなければ、
景表法上の有利誤認や、実質的に成立しない商品としての問題が生じます。

⚠ 上記は**特定時点のパラメータでの試算**です。難易度は上昇傾向にあり、
BTC 価格は大きく変動し、2028年頃には半減期で報酬が半分になります。
本システムのシミュレーターで、必ず感度分析（価格 -50%、難易度 +30%）も確認してください。
